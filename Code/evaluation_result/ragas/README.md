# AUTOSAR HLD Intelligence & Traceability Assistant - RAGAS Evaluation Pipeline

This directory contains the audited and corrected **RAGAS-based evaluation pipeline** for benchmarking the High-Level Design (HLD) Retrieval-Augmented Generation (RAG) system.

The pipeline compares the **Baseline Dense Retriever (FAISS)** against the **Architecture-Aware Hybrid Retriever (Dense + BM25 + Reciprocal Rank Fusion)** across grounded AUTOSAR architectural queries using documented HLD specification ground-truth references and source chunk IDs.

## 2. Key Corrections & Architectural Audits

### 2.1 Independent Dataset Construction
- **Separate Invocations:** Baseline and Hybrid datasets are generated by independently invoking the actual RAG pipeline (`retriever_mode="baseline"` and `retriever_mode="hybrid"`) with the same queries, document versions, and `top_k=5`.
- **No Preview Reuse:** Historical `answer_preview` fields are **never** reused across both retrievers.
- **Genuine Unsupported Query Evaluation:** For the 10 unsupported queries, actual pipeline responses are recorded into `unsupported_eval_dataset.json` rather than fabricating responses. Abstention behavior (`confidence="low"`, `review_required=True`, zero unsupported claims) is evaluated in a dedicated suite.
- **Ground Truth Integrity:** Documented specification ground-truth references and source chunk IDs are strictly preserved. Claims are not labeled as AST-verified unless directly verified against an AST model.

### 2.2 Dependency Compatibility Without Source Patching
- In modern environments, `ragas` 0.4.x attempts legacy imports from `langchain_community.chat_models.vertexai` which may trigger an `ImportError`.
- Instead of manually modifying installed files in `site-packages`, `compat.py` provides a clean, non-invasive runtime shim that stubs missing legacy modules if absent.
- Documented in `evaluation_result/requirements-eval.txt`.

### 2.3 Judge Transparency & Separation
- **Mock Judge Mode:** Kept strictly for smoke testing, schema validation, and CI checks. The summary explicitly records `judge_type: OFFLINE_MOCK_JUDGE` with a prominent disclaimer. Mock scores are never presented as genuine quality ratings.
- **Live Judge Mode:** Supports local Ollama (`qwen2.5:3b`, `qwen2.5:7b-instruct`, etc.) at `http://localhost:11434` or external LLM judges.
- **Failures & Timeouts:** Evaluator timeouts or schema errors are logged and recorded as `null` or excluded; they are **never** replaced with fake default perfect (1.0) scores.

### 2.4 Separation of Retrieval-Only vs. Generation Metrics
- **Retrieval-Only Metrics (Evaluated on Top-5 Retrieved Chunks vs. Source Chunk IDs):**
  - **Hit Rate@5:** Fraction of queries where at least one expected chunk ID was retrieved.
  - **Recall@5:** Fraction of expected chunk IDs retrieved in top-5.
  - **Mean Reciprocal Rank (MRR):** Reciprocal rank of the first relevant chunk in retrieved results.
- **Answer Generation Metrics (Evaluated via RAGAS / Judge):**
  - **Faithfulness:** Response consistency with retrieved context.
  - **Answer Relevancy:** Response relevance to user prompt.
  - **Context Precision:** Signal-to-noise ratio of retrieved context.
  - **Context Recall:** Context completeness relative to reference.
  - **Answer Correctness:** Factual and semantic alignment with reference answer.
- **Unsupported Query Abstention Suite:**
  - Evaluates abstention rate, low-confidence rate, review-required rate, and absence of unsupported claims.

## 3. Reproduction Commands

### 3.1 Dataset Dry-Run / Validation
Inspects dataset files, validates required fields, and confirms metrics support without invoking any LLM:
```powershell
.venv\Scripts\python.exe evaluation_result/ragas/evaluate_ragas.py --validate-only
```

### 3.2 Smoke Test (Fast Pipeline Verification with Mock Judge)
Runs the complete RAGAS evaluation on 2 samples across both retrievers:
```powershell
.venv\Scripts\python.exe evaluation_result/ragas/evaluate_ragas.py --mode both --sample-limit 2 --judge mock --output-dir evaluation_result/ragas/results_corrected
```

### 3.3 Live LLM Evaluation (Local Ollama)
Ensure Ollama is running (`ollama serve` with `qwen2.5:3b` available):
```powershell
.venv\Scripts\python.exe evaluation_result/ragas/evaluate_ragas.py --mode both --judge ollama --model qwen2.5:3b --output-dir evaluation_result/ragas/results_corrected
```

### 3.4 Unit & Regression Testing
Run the RAGAS evaluation suite and retrieval regression tests:
```powershell
.venv\Scripts\pytest.exe tests/test_ragas_evaluation.py -v
.venv\Scripts\pytest.exe tests/test_validation_and_retrieval_fixes.py -v
.venv\Scripts\pytest.exe tests/test_architecture_regression.py -v
```

---

## 4. Production Code Isolation

All evaluation components, shims, adapters, and results are isolated inside `evaluation_result/` and `tests/test_ragas_evaluation.py`.
Production application behavior in `app/`, `rag/`, and `ingestion/` remains completely untouched.
Historical baseline evaluation reports in `evaluation_result/ragas/results/` are preserved.
